# callCC と虚実行: 定理化のあたり (2026-11-23 のメモ。2026-11-25 に行き先を追記)

材料: 《時間泥棒の夕べ》(gigi = 排中律、nino/nicola)、《Haskell の callCC で goto を作る》(goto ループ、server/client、stop の無限ループ)。実測は callcc/hs/。

## 基本の見方

継続 = 「過去のある時点の世界(状態+残りの計算)の写し」。

- 継続を一度だけ再開する(one-shot、Python の yield) = 状態を「移動」させる = 実実行。
- 二度以上再開する(multi-shot、callCC で捕まえた k を後から呼ぶ) = 同じ時点の状態を二度読む = 状態の「コピー」 = 虚実行(定理 1)。

## 候補

### A. 葉の数 = 余分な再開の回数(易しい、Lean 向き)

逐次プログラム + callCC の実行を「世界の木」にする(k を呼ぶたびに、捕まえた時点から枝が出る)。
主張: 葉の数 − 1 = 捕まえた継続の(通常の return を一回目として)二回目以降の使用回数。
系: 継続をすべて高々一度しか使わない ⇔ 木が一本道 ⇔ 実。report0 の母関数 G(x)=Σx^{ℓ-1} の x は「継続一回の再使用の重み」と読める。
例: gigi(排中律)で query が呼ばれた実行は葉 2 つ(¬A の世界が捨てられ、A の世界が残る)。

### B. k(v) は「合流」: 木ではなく DAG

k に値 v を渡して戻ると、戻った世界は「捕まえた時点の状態」と「捨てた世界で作った v」の二つを読む。JRF の言う「成果を一部引き継ぐ」。
→ rf が木でなく DAG(二つの親)になる。これはスナップショット分離の合流(古い版 + 新しい書き込み)と同じ形で、report1(楽観的並行制御・SI)に直結しそう。
問: callCC スケジューラで実現できる rf の全体は階層のどこか(I か、合流つきの別系統か)。ELDE0 の lock 仕様の「他人の枝への乗り移り」は k(v) で書けるか。

### C. goto ループ = 時間ループの「反復」による実現

report0 の時間ループは自己無撞着(x = F(x))を要求し、実解がないとき ±i が出た。callCC の goto ループは x ← F(x) を反復する「実実行」。
- stop の無限ループ: 戻った先が同じ跳躍をもう一度起こす(F の軌道が出口に届かない周期 1 の軌道)。実測で CPU 100%・メモリ一定・出力なし。
- tan 加法の回転 F なら、反復の周期は虚の固定点 i での F'(i)=e^{2iθ} で決まる(AGENTS「解ける問題 2」)。callCC はその反復を書く自然な道具 → report3 につながる。

### D. Curry–Howard: 実 = 線形な継続、虚 = 古典論理

callCC ⇔ パースの法則・排中律(Griffin 1990)。継続を線形に使う CPS は直観主義的(Filinski、Berdine–O'Hearn–Reddy–Thielecke「Linear continuation-passing」2002 など、要照合)。
→ 「虚実行の許容 = 継続の縮約(コピー)の許容 = 古典論理への拡張」。report0 の「負数・虚数と同じ型の拡張概念」に、論理の側の対応物を与える。

## 優先度の案

A は定理として小さいが橋渡しの土台なので、report2(部品の意味)か独立の短報で Lean 化。B は report1、C は report3 に入れる。D は文献照合が先。
